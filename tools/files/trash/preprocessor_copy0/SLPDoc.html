Small Language Preprocessor (SLP)

Version: 1.0  |  Target: C++17 and later

1. Introduction

The Small Language Preprocessor (SLP) is a lightweight, JavaScript-like scripting interpreter designed to be embedded in C++ applications. It processes script definitions, maintains state across multiple evaluations, and exposes specific variables or functions as preprocessor tokens that return string values.

2. System Overview

The SLP system consists of two main components:

  • SLP Interpreter Engine: Parses and executes SLP script code, managing memory, lexical scope, and execution flow without C++ exceptions or RTTI.
  • C++ Host API: Provides an interface for the host application to load scripts, persist global state, and invoke marked preprocessor tokens with a variadic number of arguments.

3. Language Syntax & Features

3.1 Data Types

TypeDescription
undefinedUninitialized variables.
integerWhole numbers, internally implemented as uint64_t (BigInt) to guarantee full 64-bit unsigned integer support without precision loss.
floatFloating-point numbers (float64).
booleantrue or false.
string8-bit character sequences. Supports single ('...'), double ("..."'), and backtick (`...`) quotes. Backticks support ${variable} interpolation.
arrayOrdered lists of values (e.g., [1, "two"]).
objectKey-value pair collections (e.g., { key: value }).
functionCallable blocks of code defined via arrow syntax.

3.2 Operators

  • Arithmetic: +, -, *, /, %, ** (exponentiation), ++, --
  • Assignment: =, +=, -=, *=, /=, %=, <<=, >>=, &=, ^=, |=
  • Comparison: ==, !=, >, >=, <, <= (Note: == and != perform type coercion)
  • Logical: &&, ||, !
  • Bitwise: &, |, ^, ~, <<, >>
  • Conditional: condition ? true_expr : false_expr
  • Type Check: typeof <expression>

3.3 Control Flow & Functions

  • Conditionals: if, else if, else, switch (with case, default, and break)
  • Loops: for, for...in (iterates object keys or array indices), while, do...while
  • Flow Control: break, continue, return
  • Function Definition: var func = (args) -> { ... }
  • Arguments: Accessible by name and via the built-in args array (e.g., args[0]).
  • Scoping: Lexical scoping is supported. Inner functions access outer scopes. Variables declared with var inside a function are local.

3.4 Objects and Arrays

  • Object Literals: var obj = { key: value }; Access via obj.key or obj["key"].
  • Array Methods: arr.push(value), arr.unshift(value), arr.pop(), arr.shift()
  • Array Properties: arr.length returns the number of elements.

3.5 Preprocessor Directives

The #token directive registers a variable or function as a preprocessor entry point.

#token var name = 123;                 // Inline variable token
#token var namefunc = (x) -> { ... };  // Inline function token
var name = 123; 
#token name;                           // Post-declaration marking
Behavior: When accessed via the C++ API, variables return their stringified value. Functions are invoked with provided arguments and return their stringified result.

4. C++ API Reference

#include "slp.cpp"

class SLP {
public:
    // 1. Initialization: Instantiates a new, isolated interpreter state.
    SLP(); 

    // 2. Script Definition: Parses and executes the provided script. 
    // Maintains global state across multiple calls. 
    // Returns "OK" on success, or a descriptive error message.
    std::string define(const std::string& script);

    // 3. Token Execution (Variadic): Evaluates a variable or invokes a 
    // function marked with #token. Accepts a variable amount of arguments.
    template <typename... Args>
    std::string get(const std::string& token_name, Args&&... args);
};

5. Usage Example

#include "slp.cpp"
#include <iostream>

int main() {
    SLP slp;

    // Define global state and tokens
    slp.define(R"(
        #token var globalmsg = 123;
        var func1 = (x, y) -> { return x + " " + y; }
        #token func1;
    )");

    // Invoke variable token (args ignored)
    std::cout << slp.get("globalmsg") << "\n"; // Output: 123

    // Invoke function token with variadic arguments
    std::cout << slp.get("func1", 123, 124) << "\n"; // Output: 123 124

    // State persists across define calls
    slp.define(R"( globalmsg += "hi"; )");
    std::cout << slp.get("globalmsg") << "\n"; // Output: 123hi

    return 0;
}

6. Implementation & Compiler Restrictions

To ensure maximum portability and minimal overhead, the SLP implementation adheres to strict compiler constraints:

  • -fno-exceptions: No C++ exceptions (throw, try, catch) are used. Errors are handled via return types (e.g., "Error: ..." strings).
  • -fno-rtti: No Run-Time Type Information (dynamic_cast, typeid) is used. Type checking relies on explicit type tags (enums).
  • Memory Management: Uses reference-counted std::shared_ptr<Value> objects to prevent memory leaks during repeated define/get calls.

7. Testing Best Practices

Warning: Because global state persists across define() calls, tests should be scoped using curly braces { } to prevent global namespace pollution. 
// GOOD PRACTICE: Scoped execution
slp.define(R"({
    var x = 123;
    var testFunc = () -> { return x; }
    #token testFunc;
})"); // 'x' is evaluated but test logic remains isolated.
