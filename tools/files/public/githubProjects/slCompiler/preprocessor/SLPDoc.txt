1. INTRODUCTION
--------------------------------------------------------------------------------
The Small Language Preprocessor (SLP) is a lightweight, JavaScript-like scripting 
interpreter library written in pure JavaScript. It is designed to be embedded 
directly in web applications or Node.js environments. It parses and executes 
script definitions at runtime, maintains state across multiple evaluations, and 
exposes specific variables or functions as preprocessor tokens that return string 
values via a simple JavaScript API.

2. SYSTEM OVERVIEW
--------------------------------------------------------------------------------
The SLP system consists of two main components:
  1. SLP Interpreter Engine: Parses and executes SLP script code at runtime, 
     managing memory, lexical scope, and execution flow. It is optimized for 
     fast interpretation using pure JavaScript best practices.
  2. JavaScript Host API: Provides a simple interface for the host application 
     to load scripts, persist global state, and invoke marked preprocessor 
     tokens with a variable number of arguments.

3. LANGUAGE SYNTAX & FEATURES
--------------------------------------------------------------------------------
3.1 Comments
  - Single-line: // comment
  - Multi-line:  /* comment */

3.2 Data Types
  The `typeof` operator returns lowercase string identifiers for these types:
  - undefined : Uninitialized variables. (typeof returns "undefined")
  - integer   : Whole numbers. Internally implemented using JavaScript BigInt 
                to guarantee full 64-bit unsigned integer support without precision 
                loss. (typeof returns "integer")
  - float     : Floating-point numbers (standard JS Number / double). 
                (typeof returns "float")
  - boolean   : true or false. (typeof returns "boolean")
  - string    : 8-bit character sequences. Supports single ('...'), double ("..."), 
                and backtick (`...`) quotes. 
                NOTE: String interpolation (${variable}) is supported in double-quoted 
                and backtick-quoted strings, but NOT in single-quoted strings. 
                (typeof returns "string")
  - array     : Ordered lists of values (e.g., [1, "two"]). (typeof returns "array")
  - object    : Key-value pair collections (e.g., { key: value }). (typeof returns "object")
  - function  : Callable blocks of code defined via arrow syntax. (typeof returns "function")

3.3 Operators
  - Arithmetic: +, -, *, /, %, ** (exponentiation), ++, --
  - Assignment: =, +=, -=, *=, /=, %=, <<=, >>=, &=, ^=, |=
  - Comparison: ==, !=, >, >=, <, <= (Note: == and != perform type coercion)
  - Logical:    &&, ||, !
  - Bitwise:    &, |, ^, ~, <<, >>
  - String:     + (concatenation)
  - Conditional: condition ? true_expr : false_expr
  - Type Check: typeof <expression>

3.4 Control Flow
  - Conditional: if, else if, else, switch (with case, default, and break)
  - Loops: 
      * for (var i = 0; i < limit; i++) { ... }
      * for (var key in obj) { ... } (iterates object keys or array indices)
      * while (condition) { ... }
      * do { ... } while (condition);
  - Flow Control: break, continue, return

3.5 Functions and Scoping
  - Definition: var func = (args) -> { ... }
  - Arguments: Accessible by name and via the built-in `args` array (e.g., args[0]).
  - Scoping: Lexical scoping is supported. Inner functions access outer scopes. 
             Variables declared with `var` inside a function are local to that function.

3.6 Objects and Arrays
  - Object Literals: var obj = { key: value }; obj.key or obj["key"] for access.
  - Array Methods: 
      * arr.push(value)    : Adds to the end, returns new length.
      * arr.unshift(value) : Adds to the beginning, returns new length.
      * arr.pop()          : Removes and returns the last element.
      * arr.shift()        : Removes and returns the first element.
  - Array Properties: arr.length returns the number of elements.

3.7 String Methods
  The interpreter provides built-in methods for string manipulation:
      * str.charAt(index)      : Returns a new string of length 1 at the given index. 
                                 Returns an empty string ("") if the index is out of bounds.
      * str.charCodeAt(index)  : Returns the 8-bit integer character code at the given index. 
                                 Returns `undefined` if the index is out of bounds.
      * str.substring(start, end) : Returns a substring from `start` to `end` (exclusive). 
                                    If `end` is omitted, it extracts to the end of the string. 
                                    If `start` > `end`, the arguments are automatically swapped. 
                                    Indices are safely clamped to the string length.
      * str.startsWith(searchString, position) : Returns true if the string starts with the given search string. 
                                                 The optional position (default 0) specifies the index to start searching from.
      * str.endsWith(searchString, length)     : Returns true if the string ends with the given search string. 
                                                 The optional length (default string length) specifies the length of the string to check.
      * str.indexOf(searchString, fromIndex)   : Returns the first index of the search string, or -1 if not found. 
                                                 The optional fromIndex (default 0) specifies the index to start searching from.

3.8 Preprocessor Directives
  - #token Directive: Registers a variable or function as a preprocessor entry point.
  - Syntax Patterns:
      #token var name = 123;                 // Inline variable token
      #token var namefunc = (x) -> { ... };  // Inline function token
      var name = 123; #token name;           // Post-declaration marking
  - Behavior: When accessed via the JS API, variables return their stringified 
              value. Functions are invoked with provided arguments and return 
              their stringified result.

4. JAVASCRIPT API REFERENCE
--------------------------------------------------------------------------------
class SLP {
  // 1. Initialization
  constructor(); 
  // Instantiates a new, isolated interpreter state.

  // 2. Script Definition & Execution
  define(script: string): DefineResult;
  // Parses and executes the provided script at runtime. Maintains global state across 
  // multiple calls. 
  // DefineResult is an object: { success: boolean, tokens: string[], error_message: string }
  // - On success: success is true, tokens contains the names of newly defined 
  //   tokens in this call, error_message is an empty string.
  // - On failure: success is false, tokens is an empty array, error_message contains a 
  //   single descriptive error message (e.g., "Parse Error: ..." or 
  //   "Runtime Error: ...").

  // 3. Token Execution (Variadic)
  get(token_name: string, ...args: any[]): string;
  // Evaluates a variable or invokes a function marked with #token.
  // Accepts a variable amount of arguments (numbers, strings, booleans).
  // Arguments are ignored if the token is a variable.
  // Returns the result as a string, or an error string (e.g., 
  // "Error: Token not found: ...") on failure.
  // Stringification Rules: Booleans are stringified as 'true' or 'false'. 
  // Floats are stringified with up to 6 decimal places. Objects and Arrays 
  // are stringified as JSON-like representations.
}

5. USAGE EXAMPLE
--------------------------------------------------------------------------------
const slp = new SLP();

// Define global state and tokens
const res1 = slp.define(`
    #token var globalmsg = 123;
    var func1 = (x, y) -> { return x + " " + y; }
    #token func1;
`);

if (res1.success) {
    // res1.tokens will contain ["globalmsg", "func1"]
    console.log("Defined tokens:", res1.tokens);
} else {
    console.error(res1.error_message);
}

// Invoke variable token (args ignored)
console.log(slp.get("globalmsg")); // Output: "123"

// Invoke function token with variadic arguments
console.log(slp.get("func1", 123, 124)); // Output: "123 124"

// State persists across define calls
slp.define(`globalmsg += "hi";`);
console.log(slp.get("globalmsg")); // Output: "123hi"

6. IMPLEMENTATION & LIBRARY RESTRICTIONS
--------------------------------------------------------------------------------
To ensure maximum performance and reliability as a pure JavaScript library, the 
SLP implementation adheres to strict best practices:
  - Vanilla JS Only: No external dependencies, build steps, or heavy framework 
    features are used. The interpreter is written in pure, optimized JavaScript.
  - No Exceptions in Hot Paths: To maintain interpretation performance and 
    predictability, errors are handled via result objects (e.g., `DefineResult`) 
    rather than throwing JavaScript `Error` objects during normal execution flow.
  - Memory Management: Relies on JavaScript's garbage collector. Performance-critical 
    data structures may utilize native TypedArrays (e.g., `Int32Array`, `Float64Array`) 
    where beneficial, but standard JS objects and arrays are fully supported.

7. TESTING BEST PRACTICES
--------------------------------------------------------------------------------
Because global state persists across define() calls, tests should be scoped 
using block statements `{ }` to prevent global namespace pollution.

BAD:
  slp.define("var x = 123;");
  slp.define("var x = 456;"); // May cause unexpected behavior or redefinition issues

GOOD:
  slp.define(`{
      var x = 123;
      var testFunc = () -> { return x; }
      #token testFunc;
  }`); // 'x' is evaluated but test logic remains isolated to the block scope.
