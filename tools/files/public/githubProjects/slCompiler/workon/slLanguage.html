Small Language (SL) Compiler Documentation

Documentation Note: In this documentation, three backticks are never used. This prevents confusion for front-end AIs, ensuring they do not mistakenly interpret them as the end of a code block.

1. OVERVIEW

Small Language (SL) is a lightweight, high-performance programming language with C++-like syntax. It emphasizes explicit memory management, predictable data layout, and a strict separation between data structures (classes) and behavior (functions).

1.1 COMMENTS

Comments are used to document code and are ignored by the compiler.

  • Single-line comments start with // 
    // This is a single-line comment
  • Multi-line comments are enclosed in /* and */ 
    /*
This is a
multi-line comment
*/

SL provides a strict set of primitive types with guaranteed sizes.

2.1 Characters and Strings

  • Character Definition: 
    char c = 'a';
    (Must be exactly one character. Using multiple characters like char c = 'ab'; will result in a compiler error. Single quotes are strictly reserved for char).
  • String Definition: Strings (both single-line and multi-line) are enclosed in double quotes ("): 
    "This is a single-line string"
"
This is a
multi-line string
"
  • String Interpolation: Variables can be embedded directly into double-quoted strings using the ${} syntax: 
    int32 age = 25;
print("Age is ${age}"); // Outputs: Age is 25

2.3 Type Qualifiers (const)

The const keyword enforces read-only immutability for variables, pointers, parameters, and object instances. This helps prevent unintended modifications and enables compiler optimizations.

// 1. Constant variable
const int32 MAX_SIZE = 100;

// 2. Pointer to constant data (data cannot be modified)
const char* str = "hello";

// 3. Constant pointer (pointer address cannot be modified)
const int32* ptr = &some_int;

// 4. Const parameter in functions
void printValue(const int32* value) {
    // *value = 5; // Error: cannot modify a const object
}

// 5. Const explicit 'this' pointer (read-only method)
public int32 try1::getValue(const try1* this) {
    // this->x = 10; // Error: cannot modify member via const this pointer
    return this->x;
}

3.7 Miscellaneous / Special Operators

  • ?: : Ternary / Conditional operator
  • , : Comma operator
  • :: : Scope resolution operator
  • () : Function call / Type casting / Initialization
  • [] : Subscript / Array indexing operator
  • sizeof : Returns the size (in bytes) of a type or object.
  • typeof : Compile-time type introspection operator. Evaluates to the type's name as a const char* string.
  • hashtype : Compile-time type hash operator. Evaluates to the uint64 hash of the type's fully-qualified name. A result of 0 means the type is unknown.
int32 x;
const char* name = typeof(x);   // "int32", usable for printing
uint64 h = hashtype(x);         // hash of "int32"

// Comparisons: Note that comparing two const char* values with == compares their 
// memory addresses, not their string contents. To compare type names as strings, 
// use a string comparison function like cmpstr(typeof(x), "int32"). For zero-cost 
// compile-time type checking, use the hashtype operator.
if (hashtype(x) == hashtype(int32)) { } // explicit hash compare

4. FUNCTIONS

Functions are defined with a return type, name, and parameter list.

int32 strlen(char* str) {
    int16 i = 0;
    while (str[i] != 0) {
        i++;
    }
    return i;
}

5. CLASSES AND STRUCTS

Classes in SL define data layout only. By default, the compiler lays out members with normal alignment and padding for performance. For a predictable, padding-free layout (networking, serialization, file I/O), opt in explicitly with __attribute__((packed)).

5.1 Class Definition Rules

  1. No Inline Functions: Classes cannot have functions defined inside the class body. All methods must be defined externally.
  2. Access Modifiers: public, protected, and private are supported for both data members and class functions.
  3. Inheritance: Supports public, protected, and private inheritance.

5.2 Class Declaration Syntax

class classname : public classname2 {
public:
    int32 x;
protected:
    // protected members
private:
    // private members
};

5.2.1 Packed Alignment (Opt-In)

Packing is never implicit. To get a packed layout with no padding, declare it explicitly:

class classname {
    int8 a;
    int32 b;
} __attribute__((packed));

5.3 Flexible Out-of-Line Method Definitions

Functions belonging to a class are defined flexibly anywhere in the code using the scope resolution operator ::. The this pointer must be explicitly declared as the first parameter.

// Regular method with access modifier
public void classname::func(classname* this, int32 i) {
    this->x = i;
}

// Constructor (explicit this pointer)
classname::classname(classname* this) {
    // Constructor logic
}

// Destructor (explicit this pointer)
classname::~classname(classname* this) {
    // Destructor logic
}

5.3.1 Constructor Initializer Lists

SL supports C++-style constructor initializer lists, which are evaluated immediately after memory allocation but before the constructor body executes.

class MyClass {
public:
    const int32 id;
    int32& refValue;
    int32 normalValue;
};

// Constructor using an initializer list
MyClass::MyClass(MyClass* this, int32 initId, int32& initRef, int32 initNormal) 
    : id(initId), refValue(initRef), normalValue(initNormal) {
    // Constructor body executes AFTER all members in the initializer list are initialized.
}

Rules: Members are initialized in the exact order they are declared in the class definition. Base class constructors and destructors are automatically invoked by the compiler.

5.4 Static Constructors and Destructors

// Static constructor: Runs once at application startup, before main()
static classname::classname() { }

// Static destructor: Runs once when the application closes
static classname::~classname() { }

5.5 Operator Overloading

SL supports operator overloading for classes using the operator keyword. The explicit this pointer is always the first parameter.

// Overloading the array subscript operator []
public classname& classname::operator[](classname* this, int32 index) {
    // Return reference to element at index
}

5.6 Instantiation and Method Calls

classname n1;
n1.func(123); // Compiler translates this to: classname::func(&n1, 123);

5.7 Abstract Classes and Polymorphism

SL supports abstract class patterns by allowing method declarations without definitions. The compiler will not error on a missing definition as long as the method is not invoked on an instance of that exact base class.

class tryabstract {
public:
    int32 x;
};

// Declaration only (acts as an abstract method).
public int32 tryabstract::getX(tryabstract* this);

// Derived class implementing the method
class imptry : public tryabstract { };

public int32 imptry::getX(imptry* this) {
    return this->x;
}

6. MODULES AND EXPORTING

To make functions or class methods visible to other compilation units, dynamic libraries, or external linkers, use the export keyword.

export void func() { } // The export name is "func"
export(othername) void func() { } // The export name is "othername"

Forward Export: export func; or export classname::func;

Importing: #import "file.sl" includes ONLY exported symbols. #include "file.sl" performs full textual inclusion.

7. TEMPLATES

SL supports generics through templates.

7.1 Function Templates

template<A>
void func(A bla) {
    // Function logic using type A
}

7.2 Class Templates

template<N>
class try1 : public N {
public:
    N value;
};

7.3 Templated Class Method Definitions

Class-level template parameters automatically propagate into the function scope. The class name in the out-of-line definition does not need to explicitly repeat the template arguments.

template<K, V>
class Dictionary {
public:
    K key;
    V value;
};

// No need to write Dictionary<K, V>::setValue
public void Dictionary::setValue(Dictionary* this, K k, V v) {
    this->key = k;
    this->value = v;
}

7.5 Template Instantiation Syntax

Function templates support explicit instantiation (printValue<int32>(42)) or type inference (printValue(100)). Class templates always require explicit instantiation (try1<int32> t1;).

8. TYPEDEF

The typedef keyword creates an alias for an existing type without creating a new distinct type.

typedef int32 Score;
typedef char* String;

9. CONTROL FLOW

SL supports standard control flow: if, else, while, do-while, for, switch, case, default, break, continue, return.

9.1 Pattern Matching (match)

The match expression is a modern, safe alternative to traditional C-style switch statements. It is an expression (evaluates to a value), never falls through, and enforces exhaustiveness checking.

enum class Status : int32 { OK = 0, ERROR = 1, PENDING = 2 };

int32 handleStatus(Status s) {
    return match (s) {
        Status::OK => 0,
        Status::ERROR => -1,
        Status::PENDING => 1
    };
}

9.1.3 Tagged Union Destructuring (Sum Types)

enum class Result : int32 {
    Success(int32 code),
    Error(char* msg)
};

void processResult(Result res) {
    match (res) {
        Result::Success(code) => { print("Code: ${code}"); }
        Result::Error(msg) => { print("Error: ${msg}"); }
    }
}

9.2 Compile-Time Type Matching (match type)

Evaluates the static compile-time type of an expression. Inside a matched branch, the expression is smart-cast to the matched type.

template<T>
void analyze(T data) {
    match type (data) {
        int32 => { print(data + 10); }
        float32 => { print(data * 1.5); }
        MyClass* => { data->update(); }
        _ => { print("Unknown type"); } // Wildcard is mandatory for generic T
    }
}

10. DEFERRED RESOLUTION AND ORDERING

The SL compiler employs a multi-pass deferred resolution strategy. The order of declarations and definitions in the source file does not strictly matter, as long as all symbols are eventually defined within the compilation unit.

11. SUMMARY OF KEY DESIGN CHOICES

  1. Explicit this: Promotes clarity and C-style ABI compatibility.
  2. No Inline Class Methods: Keeps class definitions clean, acting strictly as data schemas.
  3. Predictable Layout On Request: Natural alignment by default; __attribute__((packed)) for padding-free layout.
  4. Static Lifecycle Hooks: Built-in startup and shutdown logic per class/module.
  5. Flexible Export Naming: Precise control over symbol names for FFI.
  6. Explicit Templating: Clear separation between class-level and method-level type parameters.
  7. Deferred Resolution: Eliminates rigid top-down ordering requirements.

12. EXECUTION MODEL AND ENTRY POINT

Every SL executable must define a global entry point function named main.

int32 main() { return 0; }
// or
int32 main(int32 argc, char** argv) { return 0; }

Lifecycle: OS loads binary → SL Runtime initializes → Static constructors run → main() called → Static destructors run in reverse → Process terminates.

13. MEMORY MANAGEMENT

SL provides low-level C-style memory management and high-level object-oriented allocation keywords. Under the hood, new and delete utilize malloc, realloc, and free.

MyClass* obj = new MyClass();
delete obj;

int32* arr = new int32[100];
delete[] arr; // Required for arrays to invoke destructors correctly

The keyword null represents a null pointer (address of zero).

14. ADVANCED TYPE SYSTEM

14.1 Reference Types (&)

References provide an alias to an existing variable. They cannot be null, cannot be reseated, and do not require explicit dereferencing.

14.2 Array Types

Fixed-size arrays decay to pointers when passed to functions. SL fixed-size arrays do NOT have a .length property or automatic runtime bounds checking.

14.3 Enumerations

enum class Direction : int8 { UP = 1, DOWN = -1 };
Direction d = Direction::UP;

14.5 Tuple Returns via Reference Displacement

To maintain strict C-ABI compatibility and optimize for WebAssembly, SL implements tuple returns as syntactic sugar for out-parameters. No hidden struct copying occurs.

// Definition with named returns.
// The compiler transforms this into: void calculate(int32* out_code, float32* out_value)
(int32 code, float32 value) calculate() {
    code = 200;
    value = 3.14;
    return; // Bare return exits the function
}

// Call Site:
int32 c;
float32 v;
(c, v) = calculate(); // Compiles to: calculate(&c, &v)

15. MODULES, IMPORTS, AND INTEROPERABILITY

  • #import "file.sl": Includes ONLY exported symbols.
  • #include "file.sl": Full textual inclusion (use with caution).
  • extern "C": Disables SL name mangling and enforces C calling convention for interoperability.

16. FUNCTIONS, SCOPE, AND NAMESPACES

16.1 Namespaces

namespace Math {
    int32 add(int32 a, int32 b) { return a + b; }
}
int32 result = Math::add(5, 10);

16.4 Anonymous Functions (Lambdas)

Lambdas can be assigned to function pointers. The compiler automatically generates a hidden thunk to bridge any captured closure state to the function pointer call, ensuring memory safety.

int32 multiplier = 5;
int32(*multiply)(int32) = int32(int32 x)->{
    return x * multiplier; // Safely copied by value into hidden closure
};

17. OBJECT-ORIENTED REFINEMENTS

17.1 struct vs class

Identical in behavior. The only difference is default visibility: class defaults to private, struct defaults to public.

17.2 Virtual Methods and Explicit Abstract Classes

A class with at least one unimplemented virtual method is strictly abstract. Classes with virtual methods receive an explicit, accessible integer field named _systemVtableIndex. This index is directly readable/writable, making objects fully serializable for network/WASM transportation without pointer invalidation.

18. EXPRESSIONS, LITERALS, AND CASTING

  • Literals: Decimal (123), Hex (0xFF), Binary (0b1010). Suffix U for unsigned, LL for 64-bit, f for 32-bit float.
  • Explicit Safe Cast: cast<Type>(expression). Performs runtime checks by comparing the object's vtable index against the target type's compile-time index.

19. ERROR HANDLING AND DIAGNOSTICS

19.1 Assertions

assert(ptr != null); halts execution and prints diagnostics if false.

19.2 Exceptions (try, catch, throw, throwable)

SL uses a lightweight, zero-overhead exception mechanism based on explicit error propagation via tuple-based error returns under the hood.

void openFile(const char* path) throwable {
    if (!fileExists(path)) {
        throw new Error("File not found"); 
    }
}

try {
    openFile("data.txt");
} catch (Error* err) {
    print("Failed: ");
    print(err->getMessage());
} catch (...) {
    print("Unknown error");
}

Under the Hood: A throwable function is lowered as a tuple-returning function. The error pair (void** err_ptr, uint64** type_id) is placed FIRST, ahead of return values and parameters. The error object is automatically deleted after the catch block finishes.

20. COMPILER DIRECTIVES AND QUALIFIERS

  • volatile: Prevents compiler optimization of accesses (essential for hardware registers).
  • inline: Suggests inlining at the call site (does not apply to class methods).
  • defer: Schedules an expression to be executed when the current {} scope exits. Invaluable for localized cleanup.
  • refclass: A class with automatic, compiler-managed reference counting.
  • auto: Local variable type inference.

21. PREPROCESSOR MACROS AND CONDITIONAL COMPILATION

Preprocessor logic blocks are enclosed between #< and #>.

#<
#token var DEBUG_MODE = true;
#token var TARGET_WASM = 1;
#>

#ifdef TARGET_WASM
extern "C" { export void wasm_specific_init(); }
#else
void native_specific_init();
#endif
Compiler Restrictions: The SLP implementation adheres to strict constraints: -fno-exceptions and -fno-rtti. Memory management uses reference-counted objects to prevent leaks.

22. VARIADIC FUNCTIONS AND COMPILER INTRINSICS

SL does not use traditional C-style va_list macros. Instead, it provides explicit compiler intrinsics for variadic argument handling to ensure seamless WebAssembly support and memory safety.

  • __builtin_va_list: Opaque type representing the argument list buffer.
  • __builtin_va_start(ap, last_param): Initializes the list.
  • __builtin_va_arg(ap, type): Extracts the next argument.
  • __builtin_va_current_type(ap): Returns the uint64 type hash of the next argument without advancing the pointer.
  • __builtin_va_end(ap): Cleans up the list (automatically injects release() for unextracted refclass objects).
void printNumbers(int32 count, ...) {
    __builtin_va_list ap;
    __builtin_va_start(ap, count);
    
    int32 i = 0;
    while (i < count) {
        int32 val = __builtin_va_arg(ap, int32);
        print("Number: ${val}");
        i++;
    }
    __builtin_va_end(ap);
}

23. TYPE AND FUNCTION IDENTITY HASHING

A single hashing scheme provides identity for types and functions, used by hashtype, typeof comparisons, match type, and variadic intrinsics.

  • Primitive types: Hashes the type name (e.g., "int32").
  • Pointer/Reference types: Base name with suffix (e.g., "int32*").
  • Classes/Structs/Enums: FULLY-QUALIFIED name, including namespace (e.g., "Math::Vector").
  • Functions: Fully-qualified name PLUS parameter types, separated by underscores (e.g., "Math::add_int32_int32"). Return types are not part of the hash.

A hash value of 0 is reserved to mean "unknown or unresolvable." The compiler defaults to using the highly efficient WyHash v4 algorithm unless a custom algorithm is specified in the C++ backend.
